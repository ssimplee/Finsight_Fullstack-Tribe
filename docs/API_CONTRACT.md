# API Contract

Base path: `/api/v1`

## Health

`GET /health`

```json
{
  "status": "ok"
}
```

## Cases

`POST /cases`

Creates a new case using the shared case fields, except `case_id` is generated by the backend.

Example request:

```json
{
  "observations": {
    "visual": ["red patches near gills"],
    "behavioral": ["surface gasping", "reduced appetite"]
  },
  "water_quality": {
    "temperature_c": 29.0,
    "ph": 7.2,
    "dissolved_oxygen_mg_l": null,
    "ammonia_mg_l": null,
    "nitrite_mg_l": null,
    "nitrate_mg_l": null
  },
  "history": {
    "symptom_duration_days": 2
  }
}
```

`GET /cases/{case_id}`

Returns the current case state.

`PATCH /cases/{case_id}`

Updates case intake fields before final report generation.

Example request:

```json
{
  "history": {
    "recent_transport": true,
    "mortality_trend": "two fish died overnight"
  }
}
```

`POST /cases/{case_id}/images`

Accepts one uploaded fish image. The current skeleton records metadata only; image storage and Qwen analysis will be added later.

Postman/Apifox setup:

- Body type: `form-data`
- Key: `file`
- Type: File
- Value: selected fish image

`POST /cases/{case_id}/follow-up`

Generates case-specific follow-up questions. Current implementation uses simple missing-field logic and mock question reasons.

Example response:

```json
[
  {
    "question_id": "Q_001",
    "question": "What is the dissolved oxygen level?",
    "reason": "Low dissolved oxygen can explain respiratory distress and surface gasping.",
    "answer": null
  }
]
```

`POST /cases/{case_id}/follow-up/answers`

Stores user answers to generated follow-up questions.

Example request:

```json
{
  "answers": [
    {
      "question_id": "Q_001",
      "answer": "3.2 mg/L"
    },
    {
      "question_id": "Q_002",
      "answer": "0.25 mg/L"
    }
  ]
}
```

`POST /cases/{case_id}/report`

Returns the current structured report state. The skeleton currently returns required follow-up questions before ranking causes.

Current mock behavior:

- If fewer than two follow-up questions are answered, response status is `needs_follow_up`.
- If at least two follow-up questions are answered, response status is `mock_report_ready`.
- Mock evidence and ranked differential are placeholders for Member 2, Member 3, and Member 4 integration.

## Source Of Truth

Use `shared/schemas/case.schema.json` and `shared/examples/case.example.json` when implementing frontend forms, backend validation, data generation, and evaluation cases.
